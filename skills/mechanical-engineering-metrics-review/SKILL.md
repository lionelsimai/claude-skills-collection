# Metrics & Outcomes Review — Mechanical Engineering

Track, interpret and act on the outcome metrics that matter for a mechanical engineer. The deliverable is a metrics dashboard definition and an interpretation/action review.
This skill is written for a mechanical engineer working with manufacturing and product clients in design offices, factories and test facilities.

## When to use
- You are a mechanical engineer preparing, delivering or reviewing this part of your work in design offices, factories and test facilities.
- You need a defensible, repeatable approach that produces a metrics dashboard definition and an interpretation/action review.
- A colleague, auditor or client asks how this was done and what evidence supports it.

## Key Concepts
| Term | Meaning |
|------|---------|
| Tolerance | the permitted variation in a dimension |
| Fatigue | weakening of material from repeated loading |
| Prototype | an early version built to test a design |

## Workflow
1. **Step 1** - Define each metric precisely — start with prototype test pass rates — including source data in design files and collection method
2. **Step 2** - Set review cadence and comparison baselines so trends, not single data points, drive decisions
3. **Step 3** - Investigate movements before celebrating or panicking: check data quality, case mix and one-off causes
4. **Step 4** - Link metric movements to practice changes and to risks such as component failures; test one change at a time where possible
5. **Step 5** - Report results honestly to stakeholders in design offices, factories and test facilities, including where outcomes fell short and what changes

## Output Format
**Context:** [Situation in design offices, factories and test facilities] | **Objective:** [What this must achieve] | **Audience:** [manufacturing and product clients and other stakeholders]

The finished output is a metrics dashboard definition and an interpretation/action review, structured as:
1. Summary of position and evidence
2. Detail, following the workflow above
3. Decisions, actions, owners and dates
4. Review point and escalation route

### Action Plan
1. **Immediate:** Confirm scope, consent and the evidence available in design files.
2. **Short-term:** Complete the workflow steps and record outcomes against prototype test pass rates.
3. **Medium-term:** Review results, close actions, and update local procedures in design offices, factories and test facilities.

## Guardrails & Quality Checks
- Never let this happen: component failures.
- Never let this happen: test safety incidents.
- Never let this happen: design tolerance errors.
- Work only within the competence and authority of a mechanical engineer; escalate or refer anything beyond it.
- Record facts and observations, not speculation, and keep records confidential to design offices, factories and test facilities's rules.
- Verify names, dates, figures and measurements twice before anything is issued or signed off.
- Use only real, verified information from the case in hand — never invent results, credentials or evidence.
